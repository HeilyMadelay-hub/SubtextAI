# Roadmap

Lines of evolution contemplated. Unless otherwise noted, they remain **outside the current scope** of the system, which is descriptive and always operates on already-persisted traces.

---

## Next Improvements

### Specialized Crisis Classifier

When request volume grows enough that the prompt-based call becomes a bottleneck, evaluate a fine-tuned model (DistilBERT or equivalent) to reduce latency and improve cost per classification. It would run alongside the prompt-based classifier, served through a lightweight AWS-hosted inference endpoint (e.g., SageMaker or a small container on App Runner) rather than through OpenRouter.

### Multilingual Support

Additional languages with language-specific prompts and evaluation pipelines.

### Document Corpus Expansion

New specialized sources without modifying governance logic. The chunking and indexing pipeline (PostgreSQL + pgvector) accepts any compatible collection.

### Audit Panel

Interface to visualize traces, compare prompt versions, and review policy activations. Built with React 19 + Recharts.

### Observability Improvements

More indicators in CloudWatch for trend detection and behavior change monitoring. Full OpenTelemetry integration across the pipeline, exported to AWS X-Ray for trace visualization.

### Deterministic Classifier Layer

Second rule-based layer over the LLM classification for regulatory audit scenarios.

### Semantic Cache

Semantic similarity caching (via Redis + pgvector) between queries to reduce model calls on equivalent messages.

This is the highest-impact item on the list. The main analysis call is both the latency bottleneck and the largest driver of OpenRouter token cost. Avoiding it on equivalent messages relieves both at once.

---

## Future Exploration

### Real-Time Streaming Analysis

Currently both analysis and replay operate on already-persisted traces, and live telemetry is limited to aggregating responses already generated by `/analizar`. The exploration would study a truly incremental analysis mode (partial, before the message is complete) during the conversation itself, potentially via WebSocket streaming. Not part of current capabilities.

### Predictive Trajectory Engine / Decision Impact

Over the already-formalized intent curves and conversational telemetry, the exploration would investigate estimating the impact of a message on subsequent turns (e.g., estimated escalation probability). This would require an independently trained and validated projection model, with its own evaluation and audit process, before it could be exposed as a reliable prediction. Current system capabilities are strictly descriptive, not predictive, and this engine is explicitly out of scope until such validation exists.
